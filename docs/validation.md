# 验证范围与已知限制

## 原工程证据与公开版证据

原部署曾使用 Apple Silicon Mac 与 iOS 系统 IKEv2 完成单设备的 IPv4/IPv6/DNS、公网蜂窝、手动重连和 Wi-Fi/蜂窝切换测试。之后仍持续修复并发、恢复与观察边界问题，所以历史成功不能证明任意后续版本和网络环境都已通过实机验收。

公开版的源码检查和离线回归只证明相应模型与代码路径。测试中模拟的内核/VICI 事件不是两台真实手机同时连接，也不是中国大陆线路测试。发布时的实际命令和结果记录于 [publication-checks.md](publication-checks.md)。

## 尚不能作出的保证

- 没有通用空白 Mac 一键部署验收；原升级模板依赖部署绑定。
- 不保证所有 macOS/iOS 版本、SDK、路由器或运营商兼容。
- 没有完成中国大陆各运营商可达性、延迟和约 200 Mbps 的验收。
- 离线多设备回归不能代替真实多设备并发及长期负载测试。
- 普通个人 VPN 配置不能保证控制所有系统级流量、GPS 或蜂窝定位。
- IPv6 当前依赖家庭宽带 IPv6 与 macOS NAT66；不等于每个客户端拥有运营商路由前缀。
- 自动重试有资源预算。持续共享资源故障仍可能需要管理员恢复，不能承诺任何错误下永不停止。

## 新部署最小验收

1. **宿主基线**：VPN 关闭时 Mac 的 IPv4、IPv6、DNS 正常，记录网络配置。
2. **单设备数据面**：蜂窝连接后 IPv4/IPv6 出口均属家庭宽带；DNS 请求路径符合配置。
3. **开关与断线保护**：主动关闭恢复本地网络；人为服务中断期间检查实际泄露行为，恢复后验证业务。
4. **重连与换钥**：手动开关、CHILD/IKE 换钥、两个方向的 Wi-Fi/蜂窝切换；记录首个新请求/视频的恢复时间。
5. **两台真实设备并发**：独立身份和地址；一台换钥/断开/撤销时，另一台业务持续可用。
6. **宿主恢复与重启**：停止、异常退出、服务器重启之后，Mac 网络和 VPN 都能按设计恢复。
7. **实际性能**：用同一手机、位置、运营商和站点做直连/VPN 对照；分别记录上下行、RTT、丢包与持续运行时间。

失败时保留与对应设备/时间段有关的最小脱敏记录。不要把含真实 IP、设备身份、令牌或完整私有配置的日志提交到公开 issue。
