# 运行与维护

## 日常使用

用户只在 iPhone 设置中开关 VPN。连接成功后仍须有业务流量才能确认数据面正常；“已连接”只表示部分控制流程成功。遇到付款等紧急业务，先由用户明确关闭 VPN，避免断线保护仍生效。

运维时分别观察：进程是否存活、IKE/CHILD 状态、对应设备 SPD/SA、转发是否就绪、双向字节计数、本机默认路由和 DNS。单个设备的换钥、移动网络切换或短暂观察不完整，不应自动解释成所有设备故障。

## 故障定位

| 现象 | 先检查 |
| --- | --- |
| 一直正在连接，无 IKE 请求 | DNS A、公网地址、CGNAT、UDP 转发、charon 监听、运营商路径 |
| IKE 认证失败 | 证书有效期、时间、SAN/IKE 身份、CA、CRL 与设备撤销状态 |
| 已连接但 IPv4/IPv6 都不通 | 设备地址分配、CHILD selector、SPD/SA、专属 PF 规则和回程 |
| 只有 IPv6 不通 | Mac 本机 IPv6、默认路由/RA、源地址、NAT66、MTU/PMTU |
| TCP 很快连接但 HTTPS 卡在 TLS | 小 HTTP 响应与 TLS 对照、客户端隧道 MTU、SYN MSS、外层分片及 ICMPv6 Packet Too Big |
| 数字 IP 可用而域名失败 | 下发 DNS、隧道内 DNS 往返、应用加密 DNS/缓存 |
| Wi-Fi/蜂窝切换恢复慢 | 旧/新 IKE/CHILD 代际、MOBIKE 观察、旧策略清理、客户端重连时间 |
| Mac 自身网络受影响 | 原有 PF 状态、默认路由、IPv6 转发/RA 和恢复日志 |
| 用量/速度显示空缺 | VICI 采样状态、身份映射、计数器重建、上传与站点鉴权 |

先读日志和当前状态，再操作对应设备。只有共享内核状态无法确认、恢复失败或全局资源损坏时，才需要关闭受影响的数据路径并恢复宿主；不能把所有异常都忽略，也不能把所有瞬时错误都升级为全体暂停。

错误按实际影响范围处理：

- 单设备的 VIP 或对端路由查询无结果、退出失败或超时，只撤下该设备的转发许可；其他设备继续经过独立的完整检查并保留转发。该设备路由恢复后自动重新准入。
- PF 状态可显示为“原始地址 → NAT 地址 → 对端”三个端点；清理检查会逐一核对全部端点。某台设备已从活动表撤下后，状态读取超时、未知格式或仍有残留，只延期该设备的重新准入，在下一轮自动重试；其他设备继续转发，不因此重启 charon。未确认清空前不会把该设备的新连接提前放行。真实删除失败、共享规则/表或所有权变化仍单独报错。
- 完整 VICI 读取出现已知超时、EOF、临时 IO 或事件容量不足时，前两次保留 charon 和 IKE 会话，关闭数据转发后在下一轮重新完整读取和审核。成功后恢复转发，不为一次观察失败重启整个守护进程。第三次连续失败才转入完整服务恢复；暂停期间不能宣称数据可用。
- 已确认的守护进程退出、已知上联网变化、定期证书撤销清单维护、持续 VICI 不可用及已知 PF 回读异常，必须完整清理及恢复核验成功才能自动重新启动。滚动 15 分钟内最多启动 3 次，用完额度后等待释放再试，不永久暂停。恢复途中中断也须重新核验后继续。
- 已恢复状态的诊断输出失败只影响日志，不把成功的恢复改成失败；真实持久记录或内核恢复失败仍单独处理。

用户停止仍优先执行。未知进程身份、配置或共享规则变化，以及恢复未通过，不属于上述自动重试类别。隔离测试覆盖设备间影响和恢复状态机，不能代替实体多设备流量及长时间运行验证。

## 与 Tailscale、SSH 和屏幕共享共存

新的防火墙事务只管理 VPN 进程及显式启用的测试探针规则。它不再阻止 SSH、屏幕共享或其他已允许的应用，也不修改系统对已签名软件的放行设置。新增、删除或修改无关应用规则，不会被解释为 VPN 故障。

已有“正常开启”的系统防火墙可以直接作为运行基线；VPN 停止后保留该模式。若原基线是“阻止所有传入连接”，启动只在 VPN 防护就绪后暂时解除该模式，停止时恢复自己改动的项目。运行时仍检查 VPN 自身规则和转发状态，不能用无关应用的状态代替这些检查。

重启后，旧运行周期中的 `ATTENTION` 只是待恢复记录。先读取本次启动的内核状态，确认旧进程、策略和端口已经释放，再清理仍能确认归属的遗留项；已经释放、删除或由其他操作修改的防火墙项目会保留，不重放旧进程或策略编号。正常开启 Tailscale、SSH 或屏幕共享不要求删除 VPN 状态或关闭系统防火墙。

这些兼容性修复不保证两个 VPN 的任意路由配置都能共存。若 Tailscale 使用出口节点、接受子网路由或修改 DNS，仍应按当前路由及解析结果定位；Tailscale 进程存在本身不能证明它导致了断网。

## 停止与恢复

使用本机部署所生成的停止/恢复入口。必须由同版本代码核实并恢复它自己管理的 PF anchor、转发开关、策略、路由与 launchd 状态。公开参考包没有原机的恢复收据，因此不能用它去“恢复”另一套现有部署。

不要将全局 `pfctl -F all`、清空全部 IPsec policy/SA 或关闭系统防火墙作为日常修复方法。它们会影响 Mac 和其他网络软件。

## 备份与升级

源码、配置模板和真实部署数据分别备份。私有备份包含 CA/服务器私钥、设备 registry、serial/CRL 事务、发布/安装收据与 root-only 配置；用加密介质保存，不要放进此仓库。监控账本按是否需要保留决定。

系统更新前保存网络基线及可恢复的发行包。更新后至少确认原生依赖能启动、Mac 双栈正常、单台设备双栈/DNS可用，以及重连和停止恢复正确。编译成功或进程存活不能代替这些验证。

证书和 CRL 到期前更新；撤销某台设备后应验证该身份不能新建连接，其他设备仍可用。域名更新任务失败时保留上次成功状态并提示，不要用空值或猜测地址覆盖 DNS。

## 性能测量

把时间分为客户端网络可用、IKE 建立、CHILD 与策略就绪、首个业务响应四段。通过蜂窝直连和 VPN 的同条件对照，区分无线链路、跨境路径、家庭宽带上行、服务器处理和目的站点的影响。

200 Mbps 是工程目标，不是已确认的容量。家庭宽带上传能力通常约束从家庭服务器发回远端手机的数据；跨境拥塞和丢包需要在真实位置测量。不要把离线 Python 回归耗时称为端到端 RTT，也不要为降低数字盲目调短所有超时或降低加密强度。

外层 IPv6 排查应保留分片和 ICMPv6 的头部证据：只过滤 `udp port 4500` 会漏掉非首分片与 Packet Too Big。确认内核 SA 计数、接口抓包与实际 HTTP/TLS 结果各自说明什么；本机发送计数或发送接口捕获不单独证明对端收到。临时 MTU 对照应限制到测试目标并恢复原路由，不先修改生产网关的全局 MTU 或 MSS。
