# Historical integration guards

The original deployment evolved through several installed release versions.
Its maintenance code checks the exact installed inventory, network ownership,
PKI history, and recovery receipts before changing system state.

`historical-control-manifests.json` and `historical-lineage.json` retain only
non-secret source lineage. They are not proof that a new host has those files,
certificates, or receipts. Old installers, private receipts, CA fingerprints,
and generated byte-embedded update programs are deliberately absent.

The release templates still contain their original guard structure. They are
not wired by `build_reference.py`: that tool only validates/packages source.
A deployable fork needs a separately implemented and reviewed fresh-install
path and locally generated bindings. Do not create placeholder historical
receipts or replace guard checks with unconditional success.
